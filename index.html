Do fork ao merge

Passo a passo para a contribuição

Nenhum grupo edita o repositório principal diretamente. Toda alteração passa por estas oito etapas, na ordem — exatamente como em um time de desenvolvimento.

01

Fork

Cada grupo cria sua própria cópia do repositório da turma.

02

Clone

O fork é copiado para a máquina do grupo para começar o trabalho.

03

Branch

Uma branch própria é criada, ex: card-grupo-01.

04

Commit

O grupo adiciona o card e registra a alteração com uma mensagem clara.

05

Push

A branch com o commit é enviada para o fork do grupo no GitHub.

06

Pull Request

O grupo abre uma PR pedindo para incorporar o card ao repositório principal.

07

Code Review

Outro grupo revisa o código: organização, padrão e funcionamento.

08

Merge

Aprovada a revisão, o card entra oficialmente na página da turma.

Sobre a atividade

Sobre

Este projeto foi desenvolvido na disciplina de Versionamento de Código e Mensageria, do 3º ano de Desenvolvimento de Sistemas da EE Dom João Nery, com o professor Yuri Batista de Brito. A proposta integra tecnologia e trabalho multidisciplinar, permitindo que os estudantes desenvolvam projetos, pratiquem Git e GitHub e aprendam, na prática, como funciona a colaboração, organização e compartilhamento de código em equipe.
